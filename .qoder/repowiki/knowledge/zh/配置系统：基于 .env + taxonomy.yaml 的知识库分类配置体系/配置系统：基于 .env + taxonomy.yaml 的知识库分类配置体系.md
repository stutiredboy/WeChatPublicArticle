## 系统概述

该仓库采用轻量级配置系统，通过环境变量（.env）加载 LLM 服务配置，结合 YAML 分类法文件（taxonomy.yaml）驱动微信公众号技术文章的自动分类与索引生成。配置系统由 Python 模块 `km/config.py` 统一管理，CLI 入口 `km/cli.py` 负责命令调度。

## 核心组件

### 环境变量加载机制
- **配置文件**：`.env`（从 `.env.example` 复制），支持 OpenAI、DeepSeek、智谱、通义、豆包等任意 OpenAI 兼容接口
- **加载逻辑**：`_load_env()` 函数按行解析 .env 文件，跳过注释和空行，使用 `os.environ.setdefault()` 设置环境变量，避免覆盖已存在的环境变量
- **关键环境变量**：
  - `KM_LLM_BASE_URL`：LLM API 基础地址（默认 `https://api.openai.com/v1`）
  - `KM_LLM_MODEL`：模型名称（默认 `gpt-4o-mini`）
  - `KM_LLM_API_KEY`：API 密钥（必填，未设置时抛出 `RuntimeError`）

### 分类体系配置
- **配置文件**：`taxonomy.yaml`，定义 11 个一级分类（AI/Agent、AIOps/SRE、GPU/TPU、存储、网络、数据中心、安全、MEM论文、职场、财经、产业、生活）
- **结构规范**：每个分类包含 `id`、`name`、`desc` 字段，描述越具体 LLM 归类越准确
- **文章类型枚举**：`article_types` 定义 8 种文章类型（技术深度、实战复盘、观点评论、教程指南、行业资讯、学术论文、方法论、生活随笔）
- **约束规则**：一级分类由用户定义，LLM 不可更改；二级细分 `sub_topic` 由 LLM 自动产出

### 路径与扫描配置
- **项目根目录**：`ROOT = Path(__file__).resolve().parent.parent`
- **输出文件**：`knowledge_index.json`（结构化索引）、`INDEX.md`（人类可读索引）
- **跳过目录**：`.git`、`.gstack`、`.playwright-mcp`、`.claude`、`.opencode`、`scripts`、`images`、`node_modules`、`__pycache__`、`km`、`.DS_Store`
- **跳过文件**：`INDEX.md`、`README.md`、`CLAUDE.md`、`AGENTS.md` 及特定生成的 Markdown 文件

## 架构设计

### 配置加载流程
1. 模块导入时执行 `_load_env(ROOT / ".env")` 加载环境变量
2. `LLMConfig.from_env()` 读取环境变量并验证必填字段
3. CLI 命令通过 `config.py` 中的常量获取路径和配置

### 数据流模式
- **Agent 驱动模式**（推荐）：`km todo` → 人工/AI 分类 → `km add` → 生成索引
- **独立模式**：`km extract` 直接调用 LLM 提取元数据
- **索引重建**：`km index` 仅重新生成 INDEX.md，不调用 LLM

### 配置验证与错误处理
- 缺少 `KM_LLM_API_KEY` 时抛出明确的 `RuntimeError`，提示复制 `.env.example`
- `km add` 命令对分类 ID 进行白名单校验，未知分类会被跳过并记录警告
- 提取失败的文章会兜底归入 `life/待分类` 分类

## 约定与约束

### 强制约束
- LLM API Key 必须设置，否则程序启动即失败
- 分类 ID 必须在 `taxonomy.yaml` 中预定义，否则被拒绝
- 输入 JSON 的 `path` 字段必须匹配 `km scan` 发现的真实文件路径

### 设计约定
- 所有配置项使用大写蛇形命名（`KM_LLM_*`）
- 配置文件使用 UTF-8 编码
- 路径使用相对路径，基于项目根目录计算
- 分类描述使用多行字符串，详细说明包含和不包含的内容

### 扩展性设计
- 新增分类只需修改 `taxonomy.yaml`，无需改动代码
- 支持任意 OpenAI 兼容接口，通过修改 `base_url` 和 `model` 即可切换
- 跳过列表可通过修改 `SKIP_DIRS` 和 `SKIP_MD` 集合进行定制
