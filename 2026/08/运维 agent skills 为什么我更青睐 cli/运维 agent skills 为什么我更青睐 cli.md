# 运维 agent skills 为什么我更青睐 cli

很多运维 skill 的底层，大概是这样子的：

- 查日志
- 看进程
- 比配置
- 跑检查
- 批量执行
- 收集结果
- 生成报告

这些动作本来就非常适合用 CLI 串起来，所以 skill + CLI 往往落地最快。

实际上就上面这个例子也可以看的出来，运维很强调流程编排，而 CLI 天然适合编排，是一个非常自然的执行底座。

另外运维 skill 很需要"确定性执行"，CLI 更容易做到。我们可以明确规定：

- 输入是什么
- 命令跑什么
- 输出文件在哪
- exit code 是什么
- 失败如何回滚
- 哪一步允许重试

这对运维特别重要，因为运维不是写 demo，很多时候是要在压力下快速复现、排障、交付结果。

因此我会认为运维场景做 agent skill，大多数时候应该"CLI 优先"，Skill 负责理解任务，cli 则更贴近现有工具链，也更容易编排成稳定流程。
